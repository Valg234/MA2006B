\chapter{Introducción}
%%============================================================

Bienvenido al \textbf{Gestor de Identidades y Documentos de Casa Monarca}. Esta aplicación fue desarrollada para ayudar al equipo de Casa Monarca, Ayuda Humanitaria al Migrante, A.B.P.\ a administrar de manera segura y ordenada la información del personal, los expedientes de migrantes y los documentos institucionales.

Con este sistema usted puede:

\begin{itemize}
  \item Iniciar sesión de forma segura con su correo y contraseña.
  \item Gestionar usuarios del sistema (si usted es administrador).
  \item Registrar y actualizar expedientes de migrantes atendidos.
  \item Subir documentos institucionales y darles seguimiento a través del flujo de revisión y firma.
  \item Firmar digitalmente documentos como coordinador, garantizando que nadie más los pudo haber autorizado.
  \item Consultar solicitudes pendientes del equipo.
\end{itemize}

\textbf{¿Para quién es este manual?}

Este manual está dirigido a todo el personal de Casa Monarca que utilizará el sistema: administradores, coordinadores, operadores y usuarios de consulta. No se requieren conocimientos técnicos de computación para seguir las instrucciones.

Cada sección indica claramente qué rol necesita para realizar cada tarea. Si una sección tiene una etiqueta como \textbf{[Solo administrador]}, significa que únicamente el personal con ese perfil podrá llevarla a cabo.

\begin{consejobox}
Si en algún momento el sistema muestra un mensaje de error o no responde como esperaba, consulte el capítulo~\ref{cap:problemas} de este manual: \textit{Solución de Problemas}.
\end{consejobox}

\section{¿Qué necesita para usar el sistema?}

El Gestor de Identidades y Documentos es una aplicación que se usa desde el navegador de internet, igual que consultar una página web. Para utilizarlo usted solo necesita:

\begin{itemize}
  \item Una computadora o laptop (Windows, macOS o Linux).
  \item Un navegador de internet actualizado: Google Chrome, Mozilla Firefox o Microsoft Edge.
  \item Conexión al servidor donde está instalada la aplicación (red local de la institución o internet, según cómo esté configurado).

\end{itemize}

El sistema \textbf{no funciona} en Internet Explorer. Use Chrome, Firefox o Edge.

\chapter{Instalación y Configuración Inicial}
\label{cap:instalacion}
%%============================================================

\begin{importantebox}
Este capítulo es para el \textbf{personal técnico} que configura el sistema por primera vez. Si usted es usuario final (coordinador, operador, consulta), puede saltar directamente al Capítulo~\ref{cap:inicio}.
\end{importantebox}

\section{Resumen del proceso de instalación}

La instalación del Gestor de Identidades y Documentos consta de cuatro pasos principales:

\begin{enumerate}[label=\arabic*.]
  \item Instalar y configurar el servidor web (XAMPP o equivalente).
  \item Importar la base de datos.
  \item Configurar la conexión de la aplicación.
  \item Poner en marcha el servidor del frontend.
\end{enumerate}

\section{Paso 1 — Instalar XAMPP}

XAMPP es el programa que actúa como servidor web en la computadora donde se instalará el sistema. Descárguelo desde \url{https://www.apachefriends.org/} e instálelo con las opciones predeterminadas.

Una vez instalado, abra el \textbf{Panel de Control de XAMPP} y presione \textbf{Start} junto a \textbf{Apache} y junto a \textbf{MySQL}.

\begin{consejobox}
Si aparece un error al iniciar Apache que dice ``Port 80 in use'', otro programa está usando ese puerto. Cierre Skype o cualquier otro servidor web que pudiera estar activo.
\end{consejobox}

\section{Paso 2 — Copiar el proyecto}

Copie la carpeta del proyecto dentro de la carpeta \texttt{htdocs} de XAMPP. En Windows, esta carpeta se encuentra en \texttt{C:\textbackslash xampp\textbackslash htdocs\textbackslash}. El resultado debe quedar así:

\begin{center}
\texttt{C:\textbackslash xampp\textbackslash htdocs\textbackslash casa-monarca-frontend\textbackslash}
\end{center}

\section{Paso 3 — Importar la base de datos}

\begin{enumerate}[label=\arabic*.]
  \item Abra su navegador y vaya a \texttt{http://localhost/phpmyadmin}.
  \item Haga clic en \textbf{Nueva} (panel izquierdo) para crear una base de datos llamada \texttt{casa\_monarca}.
  \item Seleccione la base de datos recién creada.
  \item Haga clic en la pestaña \textbf{Importar}.
  \item Seleccione el archivo \texttt{casa\_monarca.sql} que viene dentro del proyecto (carpeta \texttt{database/}).
  \item Presione \textbf{Continuar}.
\end{enumerate}

\begin{importantebox}
Asegúrese de que la importación termina sin errores. Si aparece un mensaje en rojo, verifique que el archivo \texttt{.sql} no esté dañado o incompleto.
\end{importantebox}

\section{Paso 4 — Configurar la conexión}

Abra el archivo \texttt{api/conexion.php} con cualquier editor de texto (como Bloc de notas o Notepad++). Verifique que los datos de conexión coincidan con su servidor:

\begin{center}
\begin{tabular}{ll}
\textbf{Servidor} & \texttt{localhost} \\
\textbf{Usuario MySQL} & \texttt{root} (predeterminado en XAMPP) \\
\textbf{Contraseña MySQL} & vacía (predeterminado en XAMPP) \\
\textbf{Base de datos} & \texttt{casa\_monarca} \\
\end{tabular}
\end{center}

Si su instalación de MySQL tiene contraseña, ingrésela en el campo correspondiente.

\section{Paso 5 — Iniciar el frontend}

El frontend requiere \textbf{Node.js} instalado en la computadora. Si aún no lo tiene, descárguelo desde \url{https://nodejs.org/} e instale la versión LTS.

Abra una ventana de símbolo del sistema (CMD) o terminal dentro de la carpeta del proyecto y ejecute:

\begin{center}
\texttt{npm install}
\end{center}

Espere a que finalice (puede tomar unos minutos la primera vez). Luego ejecute:

\begin{center}
\texttt{npm run dev}
\end{center}

El sistema mostrará la dirección donde está disponible la aplicación, usualmente \texttt{http://localhost:5173}. Abra esa dirección en el navegador.

\begin{consejobox}
La ventana de símbolo del sistema debe permanecer abierta mientras se usa el sistema. Si la cierra, el frontend dejará de funcionar.
\end{consejobox}

\section{Crear el primer usuario administrador}

Al importar la base de datos, se crea automáticamente un usuario administrador de ejemplo. Consulte las credenciales iniciales en el archivo \texttt{README.md} del proyecto o con el equipo técnico. Se recomienda cambiar la contraseña inmediatamente después del primer ingreso.

\section{Abrir el sistema}

Para entrar al Gestor de Identidades y Documentos, abra su navegador de internet y escriba en la barra de dirección la URL que le proporcionó el administrador del sistema. Si está en un entorno de pruebas local, la dirección usual es:

\begin{center}
\texttt{http://localhost:5173}
\end{center}

Verá la pantalla de inicio de sesión como se muestra en la Figura~\ref{fig:01-login}.

\screenshot{capturas/01-login.png}{Pantalla de inicio de sesión del Gestor de Identidades y Documentos.}{fig:01-login}

\section{Iniciar sesión}

\begin{enumerate}[label=\arabic*.]
  \item En el campo \textbf{Correo electrónico}, escriba el correo con el que fue registrado en el sistema.
  \item En el campo \textbf{Contraseña}, escriba su contraseña. Los caracteres aparecerán como puntos para proteger su privacidad.
  \item Presione el botón \textbf{Ingresar}.
\end{enumerate}

Si sus datos son correctos, el sistema lo llevará directamente al \textbf{Dashboard} (pantalla principal), donde verá su nombre, rol y las opciones disponibles para usted.

\screenshot{capturas/02-dashboard-admin.png}{Dashboard principal del sistema con sesión de administrador iniciada.}{fig:02-dashboard}

El Dashboard muestra en la parte superior el nombre del usuario y su rol, y presenta el menú de navegación con los módulos disponibles. En la imagen se observa la vista del perfil de administrador, que tiene acceso a todas las secciones del sistema.

\begin{importantebox}
Si el sistema muestra un mensaje de error, revise:
\begin{itemize}
  \item Que su correo esté escrito correctamente (sin espacios al inicio o al final).
  \item Que las mayúsculas y minúsculas de su contraseña sean correctas.
  \item Que su cuenta esté activa. Si sospecha que fue desactivada, contacte al administrador del sistema.
\end{itemize}
\end{importantebox}

\section{Entender la pantalla principal (Dashboard)}

Después de iniciar sesión, verá el \textbf{Dashboard}. Esta es su pantalla de inicio con acceso a todos los módulos del sistema. En la parte superior encontrará:

\begin{itemize}
  \item Su nombre y rol actual (por ejemplo: \textit{María García — Consulta}).
  \item El menú de navegación con los módulos a los que tiene acceso.
  \item Un botón para \textbf{Cerrar sesión}.
\end{itemize}

\begin{consejobox}
Solo verá en el menú los módulos que corresponden a su rol. Es normal no ver todas las opciones si es operador, consulta o coordinador.
\end{consejobox}

\section{Cerrar sesión}

Cuando termine de usar el sistema, presione el botón \textbf{Cerrar sesión} que aparece en la parte superior de la pantalla. Esto protege su cuenta e impide que otras personas accedan con sus datos si comparte la computadora.

\begin{alertabox}
\textbf{Nunca cierre solo la ventana del navegador} sin cerrar sesión primero, especialmente en computadoras compartidas.
\end{alertabox}

\section{Módulo: Panel de Administración}
\label{sec:admin}
%%============================================================

\textbf{Disponible para:} \fbox{Admin}

\vspace{0.4em}
El Panel de Administración es donde se gestiona el personal del sistema: crear nuevas cuentas, modificar datos de usuarios existentes y desactivar cuentas cuando sea necesario.

Para acceder, haga clic en \textbf{Administración} en el menú principal del Dashboard.

\screenshot{capturas/13-admin-panel-usuarios.png}{Panel de Administración con la lista de usuarios registrados en el sistema.}{fig:13-admin-panel}

La figura anterior muestra la tabla con todos los usuarios del sistema. Cada columna corresponde a un campo clave de la cuenta: nombre, correo, rol asignado, estado actual (activo, inactivo o revocado), fecha de vigencia y el código de certificado único generado automáticamente al crear el usuario. En la columna de acciones se encuentran los botones para editar o eliminar cada registro.

\subsection{Entender la lista de usuarios}

Al abrir el Panel de Administración, verá una tabla con todos los usuarios registrados. Cada fila muestra:

\begin{itemize}
  \item \textbf{Nombre} y \textbf{correo} del usuario.
  \item \textbf{Rol} asignado.
  \item \textbf{Estado}: \textit{activo}, \textit{inactivo} o \textit{revocado}.
  \item \textbf{Vigencia}: fecha hasta la que la cuenta es válida.
  \item \textbf{Certificado}: código único que identifica a ese usuario en el sistema.
  \item Botones de \textbf{Editar} y \textbf{Eliminar}.
\end{itemize}

\subsection{Crear un nuevo usuario}

\begin{enumerate}[label=\arabic*.]
  \item En el Panel de Administración, busque el botón \textbf{Nuevo usuario} o \textbf{Crear usuario}.
  \item Se abrirá un formulario. Complete los campos:
    \begin{itemize}
      \item \textbf{Nombre completo}: nombre del nuevo colaborador.
      \item \textbf{Correo electrónico}: será su nombre de usuario para iniciar sesión.
      \item \textbf{Contraseña}: asigne una contraseña inicial segura. Infórmesela al colaborador de forma privada para que la cambie después.
      \item \textbf{Rol}: seleccione el rol correspondiente (Admin, Coordinador, Operador o Consulta).
      \item \textbf{Estado}: déjelo en \textit{activo} para que el usuario pueda ingresar desde el primer día.
      \item \textbf{Vigencia}: fecha hasta la cual la cuenta estará activa. Después de esa fecha, el usuario no podrá iniciar sesión.
      \item \textbf{Coordinador asignado}: si el nuevo usuario es operador o consulta, seleccione el coordinador al que pertenece.
    \end{itemize}
  \item Presione \textbf{Guardar} o \textbf{Crear usuario}.
\end{enumerate}

\screenshot{capturas/14-admin-crear-usuario.png}{Formulario para registrar un nuevo usuario en el sistema.}{fig:14-crear-usuario}

El formulario muestra todos los campos necesarios para dar de alta una nueva cuenta. Es importante asignar el rol correcto desde el principio, ya que determina qué puede hacer el usuario en el sistema. Si el nuevo perfil es operador o consulta, también es obligatorio seleccionar el coordinador al que quedará vinculado.

\begin{consejobox}
El sistema genera automáticamente un \textbf{código de certificado único} para cada usuario nuevo. Este código es la identidad digital del colaborador dentro del sistema. No necesita anotarlo; el sistema lo guarda solo.
\end{consejobox}

\begin{importantebox}
La fecha de vigencia es muy importante. Si la vigencia vence, el usuario verá un mensaje de ``acceso denegado'' al intentar entrar. Recuerde revisar y renovar las vigencias periodicamente.
\end{importantebox}

\subsection{Editar un usuario existente}

Use esta opción para actualizar datos, cambiar el estado de una cuenta o extender la vigencia de un colaborador.

\begin{enumerate}[label=\arabic*.]
  \item En la lista de usuarios, localice al colaborador que desea modificar.
  \item Presione el botón \textbf{Editar} (ícono de lápiz) en su fila.
  \item Modifique los campos necesarios.
  \item Presione \textbf{Guardar cambios}.
\end{enumerate}

\screenshot{capturas/15-admin-editar-usuario.png}{Formulario de edición de un usuario existente.}{fig:15-editar-usuario}

El formulario de edición es idéntico al de creación, pero con los datos actuales del usuario ya cargados. Solo es necesario modificar los campos que cambiarán; los demás pueden dejarse sin tocar. Al presionar \textbf{Guardar cambios}, únicamente se actualizan los datos modificados.

\textbf{Casos frecuentes de edición:}

\begin{itemize}
  \item \textbf{Colaborador que se va temporalmente}: cambie el estado a \textit{inactivo}. Su cuenta queda guardada pero no puede acceder.
  \item \textbf{Colaborador que regresa}: cambie el estado de vuelta a \textit{activo}.
  \item \textbf{Vigencia próxima a vencer}: actualice la fecha de vigencia a una nueva fecha futura.
  \item \textbf{Cambio de puesto}: actualice el rol y, si aplica, el coordinador asignado.
\end{itemize}

\subsection{Eliminar un usuario}

\begin{alertabox}
Eliminar un usuario es una acción permanente. El usuario y toda su información se borran del sistema. Si solo desea que el colaborador no pueda entrar temporalmente, use la opción \textbf{Editar} y cambie el estado a \textit{inactivo} en lugar de eliminarlo.
\end{alertabox}

\begin{enumerate}[label=\arabic*.]
  \item En la lista de usuarios, localice al colaborador a eliminar.
  \item Presione el botón \textbf{Eliminar} (ícono de basura) en su fila.
  \item Confirme la acción en el mensaje que aparece.
\end{enumerate}

\subsection{Los tres estados de una cuenta}

\begin{table}[H]

\caption{Estados posibles de una cuenta de usuario.}

\toprule
\textbf{Estado} & \textbf{Significado} \\
\midrule
Activo & El usuario puede iniciar sesión y usar el sistema normalmente. \\
Inactivo & El usuario no puede iniciar sesión. Su cuenta y datos están guardados. \\
Revocado & La cuenta fue bloqueada de forma definitiva (por ejemplo, por mal uso del sistema). \\

\end{table}

\vspace{0.4em}
El Gestor de Documentos es el módulo central del sistema. Aquí se administra el recorrido de cada documento institucional, desde que se sube por primera vez hasta que queda archivado definitivamente.

\subsection{El flujo de un documento: de Ventanilla a Inserción Final}

Cada documento recorre cuatro etapas. Piense en ellas como pasos de revisión y autorización:

\begin{table}[H]
\centering
\caption{Etapas del flujo documental y quién actúa en cada una.}
\label{tab:etapas}
\begin{tabular}{p{0.08\textwidth} p{0.24\textwidth} p{0.20\textwidth} p{0.33\textwidth}}
\toprule
\textbf{Clave} & \textbf{Etapa} & \textbf{¿Quién actúa?} & \textbf{¿Qué sucede?} \\
\midrule
\textbf{V} & Ventanilla & Operador o Admin & El documento fue recibido. Se revisa y se aprueba para continuar. \\
\textbf{O} & Operador / Verificación & Coordinador & El documento está listo para firma. El coordinador lo firma digitalmente. \\
\textbf{C} & Coordinador / Firma & Admin & El documento fue firmado. El administrador hace la inserción final. \\
\textbf{A} & Inserción Final & — & El documento está archivado. Proceso completo. \\
\bottomrule
\end{tabular}
\end{table}

\subsection{Subir un documento nuevo}

  \item Escriba una breve \textbf{descripción} del contenido.
  \item Haga clic en el botón de selección de archivo y elija el archivo desde su computadora.
  \item Presione \textbf{Subir documento}.
\end{enumerate}

\textbf{Resultado:} el sistema confirma que el documento fue creado y lo agrega a la tabla en etapa \textbf{V — Ventanilla}.

\screenshot{capturas/04-formulario-nuevo-documento.png}{Formulario para registrar y subir un documento nuevo.}{fig:nuevo-documento}

La figura anterior muestra el formulario con los tres campos requeridos: título, descripción y archivo. Una vez enviado correctamente, el sistema agrega el documento a la tabla y le asigna automáticamente la etapa inicial V — Ventanilla, como se muestra a continuación.

\screenshot{capturas/05-documento-etapa-ventanilla.png}{El documento recién creado aparece en la tabla en etapa Ventanilla.}{fig:documento-ventanilla}

\end{importantebox}

Este paso significa que el documento fue revisado y está listo para pasar a la siguiente etapa.

\begin{enumerate}[label=\arabic*.]
  \item En la tabla de documentos, localice el documento en etapa \textbf{V — Ventanilla}.
  \item Presione el botón \textbf{Aprobar}.
  \item El sistema actualizará la etapa del documento automáticamente.

\textbf{Resultado:} el documento avanza a etapa \textbf{O — Operador / Verificación} y queda listo para que el coordinador lo firme.

\subsection{Firmar un documento digitalmente}

\textbf{Disponible para:} \fbox{Coordinador}

La firma digital es el equivalente a una firma manuscrita, pero con la garantía de que no puede ser falsificada. Al firmar, el sistema registra que \textit{usted específicamente}, con su contraseña de firma, autorizó ese documento en esa fecha y hora.

\begin{importantebox}
Para poder firmar, usted debe tener configuradas sus \textbf{llaves de firma digital}. Si el botón no aparece o el sistema muestra un error al ingresar la contraseña, contacte al equipo técnico: las llaves de firma se configuran una sola vez por coordinador durante la puesta en marcha del sistema.
\end{importantebox}

\begin{enumerate}[label=\arabic*.]
  \item En la tabla de documentos, localice el documento en etapa \textbf{O — Operador / Verificación}.
  \item Verifique que el archivo sea el correcto antes de firmarlo (puede hacer clic en el nombre del archivo para verlo).
  \item Presione el botón \textbf{Firmar documento}.
  \item El sistema le pedirá su \textbf{contraseña de firma} (diferente a su contraseña de ingreso).
  \item Ingrese su contraseña y presione \textbf{Confirmar firma}.
\end{enumerate}

\textbf{Resultado:} el sistema genera un \textbf{folio único de firma} y un ticket que registra: quién firmó, en qué fecha y a qué hora. El documento avanza a etapa \textbf{C — Coordinador / Firma}.

\screenshot{capturas/08-firma-coordinador.png}{Botón de firma digital disponible para el coordinador.}{fig:firma-coordinador}

La primera imagen muestra el botón \textbf{Firmar documento} visible en la columna de acciones cuando el documento está en etapa O y el coordinador tiene llaves configuradas. Al confirmar la contraseña, el sistema procesa la firma criptográfica y genera de inmediato el ticket que se muestra a continuación.

\screenshot{capturas/09-ticket-firma.png}{Ticket con el folio generado después de la firma digital.}{fig:ticket-firma}

\begin{alertabox}
\textbf{Antes de firmar, revise bien el documento.} Una vez firmado, el sistema registra que usted lo autorizó. Si firma por error, contacte al administrador.
\end{alertabox}

\subsection{Verificar si un documento fue alterado}

\textbf{Disponible para:} \fbox{Todos los roles}

El sistema puede confirmar que un documento firmado no ha sido modificado desde que el coordinador lo firmó. Esto es útil si alguien tiene dudas sobre la autenticidad de un documento.

\begin{enumerate}[label=\arabic*.]
  \item Localice el documento en la tabla.
  \item Presione el botón \textbf{Verificar firma}.
  \item El sistema mostrará un mensaje indicando si la firma es válida o si el documento fue alterado.
\end{enumerate}

\screenshot{capturas/10-verificacion-firma.png}{El sistema confirma que la firma es válida y el documento no fue modificado.}{fig:verificacion-firma}

La pantalla de verificación muestra un mensaje que indica claramente si la firma es válida o si el archivo fue alterado tras ser firmado. Cuando la firma es correcta, el sistema también despliega el nombre del coordinador firmante y la fecha exacta en que se realizó la firma, lo que permite identificar sin ambigüedad quién autorizó el documento.

\subsection{Realizar la inserción final}

\textbf{Disponible para:} \fbox{Admin}

Este es el último paso del flujo. El administrador confirma que todo el proceso fue completado y archiva el documento definitivamente.

\begin{enumerate}[label=\arabic*.]
  \item Localice el documento en etapa \textbf{C — Coordinador / Firma}.
  \item Presione el botón \textbf{Inserción final}.
  \item Confirme la acción.
\end{enumerate}

\textbf{Resultado:} el documento queda en etapa \textbf{A — Inserción Final} con la etiqueta \textbf{Finalizado}. El flujo está completo.

\screenshot{capturas/11-insercion-final-admin.png}{Botón de inserción final disponible para el administrador.}{fig:insercion-final}

La imagen muestra el botón \textbf{Inserción final} que aparece en la columna de acciones del documento cuando está en etapa C y el usuario es administrador. Al confirmarlo, el documento pasa al estado definitivo, como se aprecia a continuación.

\screenshot{capturas/12-documento-finalizado.png}{Documento archivado en etapa de Inserción Final.}{fig:documento-finalizado}

Un documento en esta etapa no puede ser revertido ni modificado. La etiqueta \textbf{Finalizado} es la confirmación de que el flujo VOCA fue completado con todas las aprobaciones registradas en el historial del sistema.

\chapter{Preguntas Frecuentes}
%%============================================================

\textbf{¿Puedo usar el sistema desde mi celular?}

El sistema fue diseñado para computadoras y laptops. Puede funcionar en un celular, pero la experiencia es mejor en una pantalla más grande.

\textbf{¿Qué significan las letras V, O, C, A en la tabla de documentos?}

Son las iniciales de las cuatro etapas del flujo documental: \textbf{V}entanilla, \textbf{O}perador / Verificación, \textbf{C}oordinador / Firma y \textbf{A}rchivo (Inserción Final).

\textbf{¿Todos los usuarios pueden subir documentos?}

Sí, cualquier usuario con sesión activa puede subir un documento nuevo. El documento aparecerá asociado al coordinador de ese usuario.

\textbf{¿Qué formatos de archivo acepta el sistema?}

PDF, Word (.doc y .docx), imágenes (.jpg y .png) y Excel (.xlsx).

\textbf{¿Quién puede aprobar un documento en Ventanilla?}

Los usuarios con rol \textbf{Operador} y los \textbf{Administradores}.

\textbf{¿Quién puede firmar un documento?}

Solo el \textbf{Coordinador} asignado al documento, y únicamente cuando el documento está en etapa \textbf{O — Operador / Verificación}.

\textbf{¿Qué pasa si firmo el documento equivocado por error?}

La firma queda registrada de manera permanente. Contacte inmediatamente al administrador del sistema para que evalúe la situación.

\textbf{¿Qué es el folio de firma?}

Es un código único generado automáticamente cuando el coordinador firma un documento. Identifica de forma inequívoca: quién firmó, qué documento, y en qué fecha y hora.

\textbf{¿Qué pasa si mi vigencia vence?}

No podrá iniciar sesión hasta que el administrador actualice su fecha de vigencia. El sistema mostrará el mensaje ``acceso denegado — vigencia expirada''.

\textbf{¿Mis datos y los de los migrantes están protegidos?}

Sí. Las contraseñas se guardan cifradas (el sistema nunca las guarda en texto legible), las llaves privadas de los coordinadores están protegidas con contraseña, y cada acción queda registrada en el historial del sistema.

\textbf{¿Puedo acceder al sistema desde casa?}

Depende de la configuración del servidor. Si el servidor está instalado localmente en las instalaciones de Casa Monarca, solo podrá acceder desde la red interna. Consulte con el área técnica si necesita acceso remoto.

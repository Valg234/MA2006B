\chapter{Introducción}

El Gestor de Identidades de Casa Monarca es una aplicación web orientada al registro, consulta y seguimiento de información operativa relacionada con usuarios, migrantes, solicitudes y documentos. Este manual se enfoca en el módulo \textbf{Gestor de documentos}, donde se administra el flujo de revisión y firma digital de documentos.

La aplicación sirve para centralizar documentos, identificar su etapa actual, controlar qué rol puede realizar cada acción y registrar la firma digital del coordinador cuando corresponde. El flujo principal del módulo se resume como \textbf{Ventanilla} $\rightarrow$ \textbf{Operador / Verificación} $\rightarrow$ \textbf{Coordinador / Firma} $\rightarrow$ \textbf{Inserción final}.

El manual está dirigido a usuarios administrativos, coordinadores, operadores y usuarios de consulta que participan en el proceso documental de Casa Monarca. También puede ser usado por personal técnico para validar el comportamiento esperado durante instalación, pruebas o capacitación.

\section{Versiones compatibles}

El frontend está construido con React, React Router y Bootstrap. Para pruebas locales se recomienda usar una versión vigente de Node.js compatible con el proyecto, un servidor PHP habilitado y una base MySQL/MariaDB configurada con la base de datos \texttt{casa\_monarca}.

\chapter{Instalación}

\section{Preparación del entorno}

Antes de iniciar, confirmar que el equipo tenga instalado el servidor web, PHP, MySQL o MariaDB, Node.js y npm. La carpeta del proyecto debe estar disponible en el servidor local para que los endpoints PHP puedan responder desde \texttt{/api}.

\section{Pasos de instalación}

\begin{enumerate}[label=\arabic*.]
  \item Copiar el proyecto en el directorio de trabajo del servidor local.
  \item Configurar la conexión a la base de datos en el archivo de conexión PHP.
  \item Verificar que la base de datos \texttt{casa\_monarca} exista y contenga las tablas requeridas.
  \item Entrar a la carpeta del frontend.
  \item Instalar dependencias con \texttt{npm install}, si aún no existen.
  \item Iniciar el frontend con \texttt{npm run dev}.
  \item Abrir en el navegador la dirección indicada por Vite.
  \item Verificar que las llamadas a \texttt{/api} respondan correctamente.
\end{enumerate}

\section{Consideraciones importantes}

Los documentos cargados por el sistema deben conservarse en la carpeta de archivos configurada para el backend. Si se mueve el proyecto de ubicación, también debe revisarse la ruta usada para visualizar los documentos. Los usuarios de tipo operador o consulta deben tener un coordinador asignado para participar correctamente en el flujo documental.

\chapter{Preguntas Frecuentes}

\textbf{¿Qué significa el flujo V, O, C, A?}

Representa las etapas Ventanilla, Operador / Verificación, Coordinador / Firma e Inserción final. Cada etapa define qué rol puede intervenir.

\textbf{¿Todos los usuarios pueden subir documentos?}

El sistema permite crear documentos desde el gestor para roles autorizados. Los usuarios operador y consulta deben tener coordinador asignado para que el documento quede vinculado correctamente.

\textbf{¿Qué formatos de archivo se aceptan?}

El backend acepta PDF, DOC, DOCX, JPG, JPEG, PNG y XLSX.

\textbf{¿Quién puede aprobar desde Ventanilla?}

El operador y el administrador pueden aprobar documentos en etapa Ventanilla.

\textbf{¿Quién puede firmar documentos?}

Solo el coordinador asignado al documento puede firmar cuando el documento está en etapa Operador / Verificación.

\textbf{¿Qué es el folio de firma?}

Es un identificador generado después de la firma digital. Permite consultar quién firmó, la fecha y la acción realizada.

\textbf{¿Por qué no aparece un botón de acción?}

El botón depende del rol del usuario y de la etapa del documento. Si no aparece, probablemente el usuario no tiene permiso para esa acción o el documento está en una etapa distinta.
